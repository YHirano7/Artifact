# aidd-llm-infographics

既存のアプリケーションに途中からAI駆動開発（AIDD）を導入するときの制御の考え方と、その前提になるLLMの仕組みを、5枚のインフォグラフィックにまとめたものです。

| ファイル | 答える問い | 結論 |
|---|---|---|
| `00-aidd-subtractive-control` | 途中導入のAIDDをどう制御するか | モデルの出力空間から、①非決定論的制約（ガイド）、②決定論的制約（センサー・ゲート）、③人の判断を順に引く |
| `01-l1-token-prediction` | モデルの中で何が起きているか | 文脈を条件に次の1トークンの確率を計算し、1つ選ぶことを繰り返している。だから①は確率を寄せることしかできない |
| `02-l2-context-assembly` | 文脈は誰が組み立てるのか | 何を載せるか・何を実行するかはハーネスが規則で決め、載ったものの解釈はモデルが確率で行う |
| `03-l3-local-llm-harness` | ローカルLLMでハーネスを自作するとき、何をどの層で縛るか | 形式はデコードで、行動はループで、正しさは外側の検査で縛る |
| `04-harness-waterfall-priority` | `00` のハーネスをウォーターフォールで運用するとき、工程ごとに何を優先して整えるか | 工程が進むほど優先される要素は ①ガイド → ②ゲート → ③人の判断 → フィードバック へ移る。上流で書いた①は、V字で対になる下流工程の②に昇格させて検査する |

`00` が結論、`01`〜`03` がその結論を支える仕組みの説明です。`01` → `02` → `03` の順に難しくなります。`04` は `00` を工程に当てはめた応用で、工程ごとに優先して直すファイルを示しています。

## ファイル形式

- `.png` — `00`〜`03` は横1920px相当、`04` は横2160px相当を2倍解像度（幅3840px／4320px）で出力した画像

## 前提と留保

- `00`・`04` のファイル名・パスは GitHub のカスタム指示・hooks・skills の仕様に基づきます。用語集（`docs/glossary.md`）や ADR（`docs/adr/`）のパスは一般的な慣習です
- 出典は各図の下部に番号付きで記載しています。数値は各出典の実験条件（モデル・設定・時点）に依存します
- 例示の確率分布や KV キャッシュの計算例は説明用の仮の値・試算で、図中にもその旨を明記しています
