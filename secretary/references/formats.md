# 説明の型（場面ごと）

## F0 型は慣習として扱う
- 文章の型やガイドラインの多くは、効果が実際に確かめられていません。確かめられているのは下の SBAR くらいです（「多くは確かめられていない」こと自体は系統レビューで示されている [A]）
- 型を「正しい形」と言わない。場面と相手から選んだ理由を一言添え、ユーザーが別の型に替えられるようにする
- 型に当てはめると不自然になるなら、型を使わずに `explain.md` の規則だけで書く

## 場面から型を選ぶ

| 場面 | 型 | 強さ |
|---|---|---|
| 相手に判断や対応を求める報告（障害・トラブル・別の職種や上位者への相談） | F1 SBAR | [A]（中程度） |
| 忙しい相手への文書・メール・チャット | F2 BLUF | [C] |
| 提案・説得（相手に納得して選んでもらう） | F3 ピラミッド | [C] |
| 短い意見表明・会議での発言 | F4 PREP | [C] |

### F5 なじみの低い相手に結論から始めるとき [C]
- BLUF や PREP で結論から始めるとき、相手のなじみ度が低ければ、結論の前か直後に、結論を理解するのに要る前提を1〜2文置く
- 前提を共有していない相手には補足が評価されやすいこと（`explain.md` の E5）と、なじみの低い相手には平易な版が合うこと（E7）から組み立てた規則で、直接確かめた研究は無い

## F1 SBAR（状況・背景・評価・提案）
話を広く物語のように伝える人と、要点だけを早く知りたい人の間の、話し方の違いを埋めるために作られた型です。導入すると安全が改善したという中程度の証拠があり、電話のように相手の顔が見えない伝達で特に効いています。送る前に、自分の評価と提案まで書けているかを確かめます。

```
【状況】いま何が起きているか（1〜2文）
【背景】判断に要る前提・経緯
【評価】自分は何が問題だと考えているか
【提案】相手に何をしてほしいか／自分なら何をするか（期限があれば期限）
```
- 【評価】【提案】はユーザーの判断です。材料に無ければ「【案】」と付けて書き、確かめてもらう
- チャットやメールで忙しい相手に送るときは、SBAR の前に「何を判断・対応してほしいか」を1行置く（F2 の考え方を重ねたもの）[C]

## F2 BLUF（要点を冒頭に）
```
<結論・依頼を1文で>
<理由・根拠を2〜3点>
<詳細・補足（必要なら）>
```
- 能動態で書く（誰が何をするかを明記する）

## F3 ピラミッド（主張と、それに対する問いへの答え）
```
主張：<いちばん言いたいこと>
 ├ なぜ？ → <理由1> ／ <理由2> ／ <理由3>
 ├ どうやって？ → <進め方>
 └ 本当に？ → <根拠・数字・例>
```
- 主張を聞いた相手が抱く問いに、上から順に答える形で積む
- 相手の問いが出尽くしたところで終える

## F4 PREP（結論・理由・例・結論）
```
結論：<…>
理由：<…>
例：<具体例>
結論：<もう一度、短く>
```
- 原典は示されていない、実務で広く使われている型として扱う
