# 会議の設計と事後の要約

会議の研究は、参加者が「良い会議だった」と感じるかとの相関を見たものが中心です。メタ分析はまだ無く、オンライン会議を直接比べた研究もほとんどありません。以下の規則は「評価と結び付いている手がかり」で、効果を保証するものではありません（M0）[B]。

## 事前

### M1 目的・成果物・成功条件を先に1文ずつ書く [B]
- **目的**：なぜ集まるのか。各議題がなぜ重要で、話し合って何を達成したいのかが参加者に分かる書き方にする
- **成果物**：終わったときに何ができているか（決定・案・一覧・論点の整理など）
- **成功条件**：何が起きれば成功か。決める会議なら「決まらなかったときの次の手順が決まる」まで含める

目的の明確さは、会議の設計要素の中でも有効性の評価と強く結び付いています。目的を言葉にする手伝いをすると、準備や伝え方が改善したという観察もあります。

### M2 開くかどうかを先に問う [B/C]
- 目的が情報の共有だけなら、文書・チャット・録画などで済ませる案を出す
- 議題のうち共有だけのものは、会議から外して事前に配る
- 呼ぶ人と議題を絞る

### M3 アジェンダは目的を伝える入れ物にする [B/C]
- アジェンダを配ること自体の効果は小さい。配って終わりにしない
- 議題を「〇〇について」と書かず、**答えるべき問い**か**つくる成果物**の形で書く
  - 例：「採用計画について」→「各チームの来期の必要人数の案を決める」
- 議題ごとに「何をつくるか（成果物）」と「どう考えるか（問い）」を分けて書くと、進め方が見えやすい

### M4 参加者は「その人に関係があるか」で選ぶ [B]
- 人数を減らすこと自体は目標にしない（人数と有効性の関係はほとんど見られない）
- 議題がその人に関係するかで呼ぶ。関係する議題だけ参加して途中で抜ける形も提案する
- 会議が本人に関係あると感じられるときに、会議の良さが成果につながりやすい

### M5 時間は「長さ」より「時刻どおり」と「割り当て」[B]
- 開始・終了の時刻を守る段取りにする（遅れて始まる会議は評価が下がりやすい）
- 所要時間に上限を置き、議題ごとに時間を割り当てる
- 会議の長さを短くすること自体は目標にしない（長さと有効性の関係は見られない）

## 進行

### M6 脱線させない・参加を促す・独演しない [B]
- 議題と目的から外れていないかを見る
- 参加を促し、発言を言い換えて確かめる。長い独演を避ける
- 会議前の雑談や前向きなユーモアは妨げない
- 上位者がいる場では、本音を隠して取り繕いやすく、それは会議の評価を下げる。口頭で順に言わせる前に、まず一人で考えて書く時間を取る進め方を提案する [C]

### M7 AI が会議中に知らせるときは、静かな形を既定にする [B]
- 「目的から外れていないか」を知らせるときは、流れを止めない形（メモ・画面の表示・終わりの振り返り）を既定にする
- 割り込んで知らせる形は、振り返りを促すのには効くが会話の流れを乱すことがある。ユーザーが選んだときだけ使う

## ラップアップ

### M8 決定事項と次の行動を読み上げて確かめる [B]
- 会議の終わりにラップアップの時間をアジェンダに取っておき、司会が次を読み上げ、その場で確かめる
  - 決まったこと
  - 次にやること（担当・期限）
  - 決まらなかったこと（未決事項）と、それをいつ・どこで決めるか
- 「終わっても何も決まっていない」は、無駄だと感じられる会議の大きな要因になる

## 事後

### M9 要約は用途で2種類に分ける [B]
- 既定で両方を出す（短い版を先に、階層の版をその後に）。片方だけでよいと言われたときだけ片方にする
- **短い版**：決定事項・次の行動・要点だけ。さっと把握したい人と共有用
- **階層の版**：議題ごとに、出た意見・論点・結論の流れを入れ子で。経緯を知りたい人用
- 決める会議では短い版を先に、話し合って考えを広げる会議では階層の版を厚めにする
- 詳しすぎる議事録はつくらない。確認の往復を増やし、かえって負担になる

### M10 元のメモにあることだけを書く [A]
- 発言録・メモに無い担当者・期限・決定・発言を足さない
- 担当や期限が書かれていない行動には「担当：要確認」「期限：要確認」と付ける
- 誰の発言か・決まったのかどうかが読み取れない箇所は、決めつけずに「要確認」とする
- 対話の要約では、言語モデルが事実と違う内容を混ぜやすい。出す前にメモと突き合わせる

## テンプレート

### 会議設計シート

```
# <会議名>（<日時>・<時間枠>）

仮置き：<ヒアリングで分からなかった前提。無ければ省く>

目的：<なぜ集まるか>
成果物：<終わったときにできているもの>
成功条件：<何が起きれば成功か／決まらなかったときの次の手順>

会議にしないもの：<共有だけの議題と、その代わりの手段（文書・チャットなど）>

参加者：
- <名前・役割> … <関係する議題>（<全部／議題2のみ など>）

アジェンダ：
| 時刻 | 議題（問い／成果物） | 進め方 | 担当 |
|---|---|---|---|
| 10:00-10:05 | 目的と成功条件の確認 | 司会が読み上げる | 司会 |
| 10:05-10:25 | <問い：〇〇をどうするか> | 各自が案を書く → 並べる → 絞る | <担当> |
| ... | ... | ... | ... |
| 10:55-11:00 | ラップアップ | 決定・次の行動・未決を読み上げる | 司会 |

事前に配るもの：<資料・比較表など>
```

### ラップアップの台本

```
時間になったので確認します。
決まったこと：
1. <決定>
次にやること：
- <行動> … 担当 <名前>、期限 <日付>
決まらなかったこと：
- <論点> … <いつ・どこで決めるか>
抜けや違いがあれば今言ってください。
```

### 事後の要約（2種類）

```
## 要点（短い版）
決定：
- <決定>
次の行動：
- <行動>（担当：<名前 または 要確認>／期限：<日付 または 要確認>）
未決：
- <論点>

## 議題ごとの流れ（階層の版）
1. <議題>
   - 出た意見：<…>
   - 論点：<…>
   - 結論：<決定／未決>
```
