# secretary

Devin CLI のスキルです。会議の設計と、説明文の整形を手伝います。

- 渡すもの: 会議の概要（目的・参加者・時間枠）、議事メモ、整形したい説明文
- 返すもの: 会議設計シート（目的・成果物・成功条件・アジェンダ）、ラップアップの台本、議事メモの要約（短い版と、議題ごとの流れを入れ子にした版）、相手に合わせて書き直した文面

## 使い方

1. `SKILL.md` と `references/` をフォルダごと、使いたいプロジェクトの `.devin/skills/secretary/` に置きます。どのプロジェクトでも使う場合は `%APPDATA%\devin\skills\secretary\`（Windows）または `~/.config/devin/skills/secretary/`（macOS / Linux）に置きます。
2. Devin のセッションで `/secretary` と呼ぶか、「会議を設計して」「議事メモを要約して」「この説明を営業向けに書き直して」のように頼みます。

## 中身

| ファイル | 内容 |
|---|---|
| `SKILL.md` | 依頼の見分け方（会議の設計／会議の事後／説明の整形／相談）、聞く項目、出す前の点検、出力の形 |
| `references/meeting.md` | 会議の規則（事前・進行・ラップアップ・事後）とテンプレート |
| `references/explain.md` | 相手のなじみ度の聞き方、3段階の書き分け、相手の質問から調整の向きを決める表 |
| `references/formats.md` | 場面から説明の型（SBAR・BLUF・ピラミッド・PREP）を選ぶ表とテンプレート |

## 作り方の方針

- 会議科学、説明の認知科学・教育心理学、平易な文章、会議支援 AI の研究を調べ、そこから規則を取り出しました。スキルはこのフォルダだけで完結し、Web の検索や外部の資料の参照はしません。出力に出典も書きません
- 規則には根拠の強さを付けています。[A]＝実験・系統レビュー、[B]＝調査・相関研究、[C]＝公式の手引き・教本・実務の慣習。会議の研究は相関を見たものが中心で、説明の型も効果が確かめられているのは一部だけです。このため、規則や型を「効果が保証される手順」としては扱いません
- 相手の知識は推測で埋めず、用語ごとに知っているかを聞きます。答えが無ければ「仮置き」と明記します
- 主張・評価・提案・数字といった中身はユーザーのものとして扱います。材料に無い中身を足すときは【案】と印を付けます

9件の評価シナリオ（会議の設計・議事メモの要約・障害報告・相手に合わせた書き直しなど）で動作を確かめています。
