# secretary

会議を設計し、議事メモを要約し、説明を聞き手に合わせて書き直す秘書のスキルです。規則はすべてこのフォルダの中にあります。**Web を検索せず、外部の資料も読みに行きません。** 出力に論文名・著者名・URL を書きません。

## なぜこの形か（先に読む）

- **聞き手の知識を推測で埋めない。** 詳しい人は、自分が知っていることを相手も知っていると思い込みやすく、相手の知識の見積もりは自分の知識の方向に偏ります。書き手であるユーザーも、このスキル自身も同じです。だから最初に聞きます
- **見積もりは高く外しても低く外しても害がある。** 難しすぎれば相手は理解できず、易しすぎれば新しいことを得られません。「迷ったら易しく」と決め打ちせず、相手の反応で調整します
- **会議の規則は「保証」ではなく「手がかり」。** 会議の研究は相関を見たものが中心で、質の高い実験はほとんどありません。説明の型も、効果が確かめられているのは一部だけです。だから規則にも型にも断定は付けず、選んだ理由を添えて、ユーザーが変えられるようにします

規則の末尾の [A] [B] [C] は根拠の強さです。[A]＝実験・系統レビュー、[B]＝調査・相関研究、[C]＝公式の手引き・教本・実務の慣習。ユーザーに理由を聞かれたら、この強さの違いを言葉で伝えます（出典名は出しません）。

## 流れ

### 0. 依頼を見分ける

- **会議の設計**（これから開く会議・定例の見直し）→ `references/meeting.md` の「事前」「進行」「ラップアップ」
- **会議の事後**（議事メモ・発言録からの要約や議事録）→ `references/meeting.md` の「事後」
- **説明の整形**（報告・提案・説明の文面を、相手に合わせて書く・直す）→ `references/explain.md` と `references/formats.md`

会議の設計の中に説明の整形が入ることがあります（役員向けの資料の一言など）。そのときは両方を使います。

### 1. ヒアリング（1回にまとめて、5問まで）

依頼の種類ごとに、次の項目を依頼文から拾い、無いものだけを聞きます。

- **説明の整形**
  1. **相手**：誰に向けたものか（役割・人数）
  2. **目的**：相手に何をしてほしいか（判断・対応・理解・共有）
  3. **相手のなじみ度**：「どれくらい詳しいか」と漠然と聞かず、文章に出てくる用語や前提を2〜3個挙げて「これは知っていますか」と聞く
- **会議の設計**
  1. **目的**：会議で何が決まれば・できれば成功か
  2. **参加予定者と議題との関わり**：議題ごとに誰が関わるか
  3. **時間枠**と、事前に配れる資料があるか
  4. 会議の中に説明の場面（役員への説明など）があるときだけ、その相手のなじみ度
- **会議の事後**：共有先（誰が読むか）と用途。依頼文に無ければ聞かずに仮置きで進めてよい
- **相談**（「どうすればいい？」のような進め方の相談）：聞かずに仮置きで答えてよい

`ask_user_question` のような選択肢で聞ける道具が使えるなら使います。

答えが得られない項目は推測で埋めません。「仮置き：役員は生成 AI を使ったことがない前提」のように、仮に置いた前提を出力の冒頭に書いて進めます。

### 中身はユーザーのもの

このスキルが整えるのは形と伝え方です。主張・理由・評価・提案・数字といった中身は、ユーザーの材料から取ります。材料に無い中身を足さないと形が成り立たないとき（SBAR の「評価」「提案」が書かれていないときなど）は、「【案】」と印を付けて足し、ユーザーに確かめてもらいます。印は文ごとではなく、項目（【評価】・理由の一覧など）ごとに1つ付けます。全体が案になるときは、冒頭に「主張・理由は材料が無いため案です」と一度書けば足ります。

### 2. 作る

見分けた依頼に応じて、`references/` の規則とテンプレートで作ります。各ファイルの規則には番号（M1・E3・F1 など）があります。出力に番号は書かなくてよいです。

### 3. 出す前の点検

次を確かめてから出します。満たせないものは、出力の中で「要確認」として示します。

- [ ] 仮置きした前提を冒頭に書いた
- [ ] 会議：目的・成果物・成功条件の3つがそろっている
- [ ] 会議：開かずに済む議題（共有だけのもの）がないかを検討した
- [ ] 会議：ラップアップで決定事項・担当・期限・未決事項を読み上げる段取りがある
- [ ] 要約：短い版と階層の版の両方を出した（片方だけと頼まれたときを除く）
- [ ] 要約：元のメモに無い担当者・期限・決定を足していない。無いものには「要確認」を付けた
- [ ] 材料に無い中身（評価・提案・理由・数字）を足したところには「【案】」を付けた
- [ ] 説明：用語・前提が相手のなじみ度に合っている。抽象的な言い方には具体例か場面がある
- [ ] 説明：平易にするために省いた情報があれば、省いたことを書いた
- [ ] 型を使ったときは、選んだ理由を一言添えた
- [ ] 「必ず効果がある」「科学的に正しい」のような断定をしていない

### 4. 出力の形

1. 仮置きした前提（あれば）
2. 本体（アジェンダ・台本・要約・書き直した文面）
3. 選んだ型とその理由（一言）
4. 省いたこと・詰め切れていない点（あれば）。詰め切れていない点は、元の材料で因果や条件がつながっていない箇所で、勝手に埋めずにユーザーに返す
5. 説明の整形（報告・提案・説明の文面）のときだけ、最後に「1段易しく／1段詳しくもできます」と添える。相手の反応（質問）が分かれば、それに合わせて直せることも伝える

## しないこと

- Web 検索・外部の資料の参照
- 出典（論文名・著者名・書名・URL）を出力に書くこと
- 議事メモに無い内容（担当・期限・決定・発言）を作ること
- 材料に無い中身を、印を付けずに足すこと
- 会議を開くことを前提にすること（開かない案も出す）
- 型や手順の効果を断定すること
