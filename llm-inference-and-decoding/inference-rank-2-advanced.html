① vLLM V1 APC ブロック連鎖ハッシュ（Chain Hash）と BlockPool SHA256 / CBOR 決定論化
・ハッシュ連鎖構造［vLLM Design Docs / Zenn V1解説］：各ブロック（16 tok）のハッシュを hash(Parent_Hash, Block_Tokens, Extra_Hash[LoRA_ID / Image_Hash / cache_salt]) として計算し、満杯ブロック（full blocks）のみを BlockPool に登録。find_longest_cache_hit() で先頭から検索し、1トークンでも変われば以降の全ブロックハッシュが連鎖的に不一致となる。
・逆順退避：リクエスト完了時（ref_cnt == 0）、末尾ブロック（より長いプレフィックスに依存し再利用確率が低い）から先にフリーキューへ戻し、先頭（System Prompt）を長く残す。
② RadixAttention (SGLang) 基数木（Radix Tree）によるKV保持＋LRU退避 最大 6.4× スループット向上 [Zheng+ 2024]
リクエスト完了後もKVキャッシュを破棄せず、可変長トークン列をエッジに持つ Radix Tree（圧縮トライ木） としてGPUメモリ上に保持。新規リクエストは根から最長一致検索してKVを再利用し、メモリ満杯時は参照カウント0の葉ノードからLRU退避。さらに共通プレフィックスを持つ待機リクエストを優先実行する Cache-Aware Scheduling（DFS近似） により、エージェント・Few-shot・マルチターン対話でレイテンシを最大 3.7×削減（木の管理オーバーヘッドは100リクエスト74.3秒中わずか0.2秒未満）。
③ 長文脈KV退避 & P/D制御 Attention Sink / H2O / SnapKV / Chunked Prefill 400万tok対応・最大 29× 高速化
・StreamingLLM［Xiao+ ICLR 2024］：Softmaxの和が1になる制約上、モデルは無関係な先頭4トークンを「Attention Sink（余剰スコアの捨て場）」として使う。単純なWindow Attentionが破綻する原因はこの先頭トークン喪失にあり、先頭4 Sink＋直近スライディング窓を残すだけで 400万トークン超を安定処理（再計算比 22.2×高速化）。
・H2O［Zhang+ NeurIPS 2023］& SnapKV［Li+ 2024］：累積Attentionスコア上位のHeavy-Hitter（20%予算）＋直近KVのみ残す動的劣モジュラ退避でスループット最大 29×向上（H2O）。プロンプト末尾Observation窓のAttentionから重要クラスタを1パス抽出（SnapKV: 3.6×高速化・8.2×省メモリ）。
・Sarathi-Serve［OSDI 2024］& DistServe［OSDI 2024］：長文Prefillをチャンク分割してDecodeに相乗りさせる Chunked Prefill（vLLM V1既定）、またはPrefillとDecodeを別GPUに分離し干渉をゼロ化。

【Nucleus Sampling (Top-p)［Holtzman+ ICLR 2020］】 平坦な分布では小さい k が語彙を狭めすぎ、尖った分布では大きい k が低確率のゴミトークンを拾う。累積確率 ∑ P(x) ≥ p の最小集合 V^(p) で候補数を動的伸縮させる。 分布形状への適応
【Min-p Sampling［Nguyen+ ICLR 2025］】 高温（τ=1.5等）ではTop-pでも裾の無関係トークンが混入する。最上位トークンの確率 p_max に比例する閾値 p_base × p_max 未満を切り捨て、高確信時は厳格・不確実時は多様にする。 高温でも破綻しない創造性
【ハーネスの Response Prefill 3モード［Manus 2025 / Hermes形式］】 ツール定義を動的に消すと先頭KVキャッシュ（10倍差）が壊れるため、アシスタント応答先頭を事前入力して行動空間を絞る：

⚡ Anthropic Prompt Caching の実測経済性と破綻条件［Anthropic 2024-2026 / Manus 2025］：

④ Outlines 有限状態機械（FSM）と語彙インデックス σ : Q → P(V) マスク取得 O(|V|) → 平均 O(1)
正規表現やJSON Schemaを有限状態機械（FSM）に変換。素朴な実装では毎ステップ語彙全体（|V| = 50,257〜128,256）を走査して有効トークンを判定するため O(|V|) の致命的遅延が生じる。Willard & Louf (2023) は生成前に語彙全文字列をFSM上で部分マッチングさせ、各FSM状態 q ∈ Q から受理可能なトークン集合を引くハッシュマップ σ を前計算することで、実行時のマスク生成を 平均 O(1) に落とした。
⑤ Compressed FSM (SGLang) 単一遷移パス圧縮と Jump-Forward Decoding レイテンシ最大 2× 削減 [LMSYS 2024]
トークン単位FSMは {"name": " のような確定文字列でも「1ステップ1トークン」ずつDecodeを回す弱点がある。SGLangは正規表現FSMの分岐がない単一遷移エッジを1本の文字列に圧縮し、確定文字列を一括トークン化して Prefill（1回のForwardパス）で複数トークンをジャンプ前進させ、通常の非制約デコードより速いJSON生成を実現（トークン境界は再トークン化で厳密処理）。
⑥ XGrammar (MLSys 2025) PDA＋文脈独立トークンキャッシュ＋永続スタック CFGで最大 100× 高速化 [Dong+ 2025]
再帰を含む文脈自由文法（CFG / 任意JSON・関数呼出・コード）はスタックを持つ Byte-level Pushdown Automaton (PDA) が必要になる。XGrammarは語彙を ①文脈独立トークン（スタック先頭位置だけで合否が決まる・語彙の99%超） と ②文脈依存トークン（親ルールへのPopを伴い全スタック検査が必要・1%未満） に分割。①を Adaptive Token Mask Cache に前計算し、②を木構造の Persistent Stack で高速検査＋CPUマスク生成とGPU実行を並列オーバーラップさせ、エンドツーエンドでほぼゼロ遅延を達成。

概念比較①：vLLM Hash-based APC（ブロック連鎖ハッシュ）vs SGLang RadixAttention（基数木） vLLM Docs / Zheng+ (2024)
vLLM APC：固定サイズ（16 tok）の満杯ブロックごとに親ハッシュを連鎖させたSHA256/CBORハッシュでグローバル辞書を引く（ファイルシステムのコンテンツアドレス記憶に近い）。
SGLang RadixAttention：可変長トークン列をエッジに持つ基数木（Radix Tree）で全リクエストのKVと分岐構造を直接保持し、LRU退避とDFSキャッシュ優先スケジューリングを一体実行する。
概念比較②：JSON Mode（Legacy）vs Structured Outputs（Strict CFG）vs 意味検証レイヤー libercraft (2026) / XGrammar
JSON Mode：壊れていないJSON構文のみを保証し、必須キー欠落や型違反は防げない。
Structured Outputs（Strict）：FSM/CFGのLogitマスク（-∞）でスキーマ・型・enum準拠を生成時に100%強制する。意味検証レイヤー：生成された値がドメイン規則（明細合計一致など）を満たすかを検証する第3の層。
概念比較③：StreamingLLM（Sink固定）vs H2O（累積スコア動的退避）vs SnapKV（末尾窓1パス） Xiao+ (2024) / Zhang+ (2023) / Li+ (2024)
StreamingLLM：先頭4トークン（Sink）＋直近窓のみを残し、無限長ストリームのPerplexity崩壊を防ぐ（中間情報は捨てる）。
