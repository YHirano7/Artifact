推論基盤・中級 / Rank I

Prefillは「計算律速（行列×行列）」、Decodeは「HBM帯域律速（行列×ベクトル）」であり、SRAMタイリング・ページング・KV共有で壁を突破する

対象：①Prefill vs Decode / Roofline / FlashAttention / PagedAttention / GQA
中級の核心結論：LLM推論は1トークン目（Prefill: TTFT）と2トークン目以降（Decode: TPOT）で物理的特性が180度逆転する。過去20年で演算は90,000倍に対しメモリ帯域は100倍しか伸びておらず［Gholami+ 2024］、HBM I/O削減（FlashAttention）・KV断片化排除（PagedAttention）・KVヘッド削減（GQA）が必須となる。

LLM Autoregressive Inference Pipeline & GPU Memory Hierarchy（Prefill → KV Cache → Decode の物理データフローとRoofline相転移） TTLT = TTFT + TPOT × (n - 1) [Magalhaes] ｜ エージェントでは入出力トークン比が 100:1 に偏る [Manus 2025]
層A：Prefill Stage（入力プロンプト並列一括処理・Compute-Bound） 指標：TTFT（Time To First Token）
① 並列GEMM計算 全入力トークン s 個の行列×行列積（Matrix-Matrix） 演算強度 I ≈ 1024 OPs/B
プロンプトの全トークンが既知のため、重み行列を1回HBMから読むだけで s 個のトークンベクトルと同時に積和演算できる。Llama-2-7B（seq=2048, B=1, A6000）では q/k/v/o/gate/up/down proj すべてが演算強度 1024 OPs/byte で Compute-bound（155 TFLOP/s）に到達し、GPU演算器を飽和させる［Yuan+ 2024 Table 1］。
② FlashAttention SRAMタイリング＋Online Softmaxによる N×N 行列の非実体化 GPT-2で 7.6× 高速化 [Dao+ 2022]
・標準Attentionの壁：スコア行列 S = QK^T と確率行列 P = softmax(S)（サイズ N×N）を低速なHBM（1.5〜2.0 TB/s, 40〜80GB）に書き戻すため、Θ(Nd + N²) のHBMアクセスが発生［Dao+ NeurIPS 2022］。
・IO-Aware Tiling：Q, K, V を小ブロックに分割して高速なオンチップSRAM（19 TB/s, 192KB/SM）に載せ、行ごとの最大値 m と指数和 ℓ を逐次更新する Online Softmax で QK^T → softmax → PV を単一CUDAカーネルに融合。HBMアクセスを Θ(N²d²M⁻¹)（MはSRAMサイズ）へ削減（HBM R/W 40.3GB → 4.4GB、定理2・命題3で漸近最適性を証明）。
③ FlashAttention-2 Work Partitioning と非Matmul演算削減 最大 225 TFLOPs/s (73% Peak)
FlashAttention v1はA100理論ピークの25〜40%に留まった。v2は (1) 非Matmul FLOPsの削減（出力の再スケーリングをループ末尾へ遅延）、(2) 単一ヘッドでも系列長（Query行ブロック）方向でThread Block並列化してOccupancy向上、(3) Warp間でQを分割（K/V共有）しShared Memory通信を削減して 約2×高速化（50〜73% FLOPs利用率）を達成［Dao 2023］。
⚡ 注意の誤解防止［Evaltude / Open LLM Eng］：FlashAttentionは「1回のパス内で N×N 中間行列をHBMに実体化しない」アルゴリズムであり、Decodeステップ間で保持し続ける永続KVキャッシュのバイト数自体は減らさない（永続KV削減にはGQA・PagedAttention・KV圧縮が要る）。

層B：RooflineモデルとMemory Wall（相転移の物理法則） P ≤ min(P_peak, B_peak × I)
ハードウェアのRidge Point（均衡点）と演算強度 I = FLOPs / Bytes 20年で演算90,000× vs 帯域100× [Gholami+ 2024]
【Ridge Point 右側：Compute-Bound（平坦な屋根）】 H100 SXM BF16: 989 TFLOP/s ÷ 3.35 TB/s ≈ 295 FLOP/B（A100は約105〜156）。Prefill（I ≈ s）はここに位置し演算器律速。 指標：MFU
【Ridge Point 左側：Memory-Bound（斜めの屋根）】 Decode（B=1）は重み 2N バイトを読み 2N FLOPs しか計算せず I ≈ 1 FLOP/B（均衡点の1/200以下）で演算器が遊休［Magalhaes］。 指標：MBU
【Attention演算強度の一般式［FlashInfer 2024］】 クエリ長 l_q、KV長 l_kv に対し I = O(1 / (1/l_q + 1/l_kv))。Prefill/Appendは O(l_q)、Decode（l_q=1）は常に O(1) で完全IO律速。 バッチ化でもKV読出は不変
【Model Bandwidth Utilization (MBU)［Databricks 2023］】 MBU = ((Params + KV_Size) / TPOT) / Peak_BW（7B FP16 14GBをTPOT 14msで処理→実効1TB/s、Peak 2TB/sならMBU 50%）。 Decode効率の正規化指標
KVキャッシュの役割 なぜKVキャッシュが要り、なぜバッチサイズの天井を決めるのか OPT-13B (A100 40GB) でVRAMの >30% 占有
Causal Maskにより過去トークンのKey/Value投影は後続トークンで変化しない。KVキャッシュは過去位置のK/V再投影を O(N²) → O(N) に省くが、毎Decodeステップで全過去トークンのK/VをHBMから読み直す必要がある。さらにバッチサイズ512・文脈長2048ではKVキャッシュだけでモデル重みの3倍（最大3TB）に達し［Pope+ 2022 / Weng 2023］、GPUメモリの空き容量が同時処理バッチ数の上限を決める。
⚡ 容量と帯域の二重ボトルネック［k44-watanabe 2026］：KVキャッシュは①容量ボトルネック（空きブロック枯渇によるプリエンプション発生）と②帯域ボトルネック（長文脈Decodeで毎ステップ過去K/Vを読むHBM転送遅延）の2面で推論性能を制約する。

層C：Decode Stage（自己回帰1トークン生成・Memory-Bandwidth-Bound） 指標：TPOT / ITL（Inter-Token Latency）
④ 逐次GEMV計算 1トークン×全重み読出＋バッチ化による重み償却 Llama-2-7B Decode: I = 0.25〜1.75
単一ストリーム（B=1）のDecode速度は TPOT ≥ Weight_Bytes / Bandwidth で下限が決まる（8B BF16 16GB ÷ 3.35 TB/s ≈ 4.8ms → 上限約210 tok/s）。b シーケンスをバッチ化すれば重み読出は1回で b 回使われ重みMatmulの演算強度は I ≈ b に上がるが、各リクエスト固有のKVキャッシュ読出はバッチ化では償却できない［TechAIInterview / Magalhaes］。
⑤ PagedAttention (vLLM) OS仮想メモリ式ブロック管理＋Copy-on-Write スループット 2〜4× 向上 [Kwon+ 2023]
・既存システムの浪費：最大長（例: 2048 tok）の連続領域を事前確保するため、実トークンに使われるKVメモリはわずか 20.4%〜38.2%［Kwon+ SOSP 2023 Fig.2］。
・非連続ページング：KVキャッシュを固定長ブロック（既定16 tok）に分割し、Block Table で論理ブロックを任意の物理ブロックへ写像。内部断片化を「各リクエスト最後の1ブロック未満」に抑え外部断片化をゼロ化。
・Copy-on-Write共有：並列サンプリングや共通プロンプトで物理ブロックを参照カウント共有し、書込衝突時のみ融合カーネルでブロック複写（メモリ最大 55%削減）。
⑥ MQA & GQA Queryヘッドのグループ化によるKV容量・HBM読出帯域の大幅削減 5% UptrainingでMHA同等品質
・MQA［Shazeer 2019］：全 H 個のQueryヘッドで単一のKey/Valueヘッドを共有しKV帯域を 1/H に削減するが、品質劣化や学習不安定が起きる。
・GQA［Ainslie+ EMNLP 2023］：Queryヘッドを G グループ（例：G=8）に分け各グループで1組のK/Vヘッドを共有。既存MHAのK/V投影行列をグループ内で Mean Pooling し元学習量の 5% だけ追加学習（Uptraining）することで、MHAに近い精度とMQA並みの高速Decode（T5-XXLでMHA 1.51ms → GQA-8 0.32ms）を実現。

① KVキャッシュ容量の厳密式 Llama-2-70B実測
1リクエストのKVサイズ＝2(K,V) × n_layers × n_kv_heads × d_head × seq_len × bytes。Llama-2-70B（GQA）は重み140GB（FP16）に対し、seq=1024・B=64でKVが20GB（FP16）/ 10GB（INT8）を消費する。
出典: Databricks (2023) Table 3 / Weng (2023)
② Continuous Batching Iteration-Level
Static Batchingはバッチ内最長系列が終わるまで全スロットが待つ。Iteration-level scheduling（Orca / vLLM）は1トークン生成ごとに完了系列を即座に外し、待機中の新規リクエストを途中挿入してGPU遊休を防ぐ。
出典: Kwon+ (2023) §2.2 / k44-watanabe (2026)
③ KV枯渇時のプリエンプション Swap vs Recompute
同時生成中に物理KVブロックが枯渇すると、FCFSで後発リクエスト群を退避する。Swapping（PCIe経由でCPU DRAMへ退避）とRecomputation（物理ブロックを破棄し再開時にPrefill再計算、vLLM V1の主軸）の2方式がある。
出典: Kwon+ (2023) §4.4 / Qiita vLLM V1解説
④ Online Softmaxの再スケール Algorithm 1
ブロックごとに局所最大値 m_new = max(m_i, m̃_ij) と正規化分母 ℓ_new = e^(m_i - m_new)ℓ_i + e^(m̃_ij - m_new)ℓ̃_ij を追跡し、部分出力 O_i を補正することで、全列を見ずに厳密なSoftmaxを1パス計算する。
出典: Dao+ FlashAttention (2022) L283-322
⑤ Tensor ParallelismとTTFT TP=1→4→8
重みとKVキャッシュを複数GPUへ分割（TP）すると、1GPUあたりのHBM読出量が減りTPOTと長文PrefillのTTFTが大幅改善する（ただし層ごとのAll-Reduce通信オーバーヘッドとのトレードオフになる）。
出典: Databricks (2023) / Gholami+ (2024)
⑥ Attention Backend実測比較 vLLM vs SGLang
Qwen3.5-4B-FP8（B=1）での実測では、同一フレームワーク内のBackend差（FlashAttention / FlashInfer / Triton）は誤差範囲だが、ランタイム自体のCPUオーバーヘッド差（vLLM vs SGLang）がDecode速度に直結する。

概念比較①：MFU（Model Flops Utilization）vs MBU（Model Bandwidth Utilization） PaLM (2022) / Databricks (2023)
MFU：ピーク演算性能（TFLOP/s）に対する達成FLOP/sの比率。学習時や長文Prefill・超巨大バッチなど Compute-bound 領域 の効率を表す。
MBU：ピークメモリ帯域（TB/s）に対する (Params + KV_Size) / TPOT の比率。小〜中バッチの Decode（Memory-bound領域） でハードウェア帯域をどれだけ引き出せたかを表す。
概念比較②：FlashAttention（計算カーネル最適化）vs PagedAttention（KVメモリ配置最適化） Dao+ (2022) / Kwon+ (2023)
FlashAttention：1回のフォワードパス内でSRAMタイリングにより N×N スコア行列のHBM往復を消す（主にPrefill/学習のI/Oと一時メモリを削減）。
PagedAttention：DecodeステップをまたいでHBMに常駐するKVキャッシュをページ分割・非連続配置し、断片化（60〜80%浪費）を消して同時実行バッチサイズを2〜4倍に増やす。両者は直交し併用される。
概念比較③：MHA（Multi-Head）vs MQA（Multi-Query）vs GQA（Grouped-Query） Shazeer (2019) / Ainslie+ (2023)
MHA：Query・Key・Valueがすべて H ヘッド（最高表現力だがDecode時のKV読出帯域が重い）。MQA：K/Vを1ヘッドに集約（最速だが品質劣化）。
GQA：K/Vを G ヘッド（例：8）にし、既存MHA重みのMean Pooling＋5%追加学習でMHA同等の精度とMQA同等の推論速度・KVメモリ1/8化を両立（Llama 2/3等の標準）。
